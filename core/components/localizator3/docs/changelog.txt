# Changelog

All notable changes to Localizator3 are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

---

## [Unreleased]

## [1.1.7-beta] - 2026-11-24

### Fixed
- pdoPage ajax («Показать ещё») keeps the storefront language. The connector calls `OnHandleRequest` again with no page path, and that call no longer switches back to the root language or changes `base_url`.
- Listing image and file TVs stay at the site root when the media source has `baseUrlRelative` off. The language base `/en/` is not left on the picture URL.

## [1.1.6-beta] - 2026-11-23

### Fixed
- Listing `uri` stays the document path. A menu link `href="{$uri}"` on a base `/en/` no longer becomes `/en/en/`. `link` is still `/en/page.html`.
- Saving a translation no longer turns it off. The form sent `active` as the string `true`, and that was stored as `0`, so the menu kept the document title.
- Turning a translation on, or saving it, no longer returns HTTP 500 when a date TV has a value. `strftime()` is deprecated on PHP 8.1, and the connector reports that warning as an error. The date is stored with `date()`.

## [1.1.5-beta] - 2026-11-23

### Fixed
- `makeLocalizedUrl` and `getLocalizedCanonical` drop a language host whose scheme is not `http` or `https`. The language switcher already did this.
- Direct `pdoMenu` and `pdoResources` overlay the same resource fields as `getLocalizedResources`. A second `localizator` join is not added when the wrapper already supplied one.
- Listing `uri` for a language base such as `/en/` is `en/page.html`, and `link` is `/en/page.html`. A template that prefixes `/` stays on that language. The default language base `/` is unchanged.
- Translator HTTP calls stop after 5 seconds to connect and 15 seconds for the response.
- `getLocalizedSitemap` skips resources with `searchable = 0`.
- With `onlyWithLocalization`, a page that has a translation still lists the default language from the document. `x-default` stays on that language.
- An unpublished translation (`active = 0`) is no longer applied on the page or returned by `getLocalizedField` and `locfield`. The page, the field snippet and `getLocalizedResources` all require `active = 1`. A localized TV is read only when that published row exists.
- With `localizator3_default_from_resource`, `getLocalizedResources` no longer copies a document field into an empty translation cell. A resource with no translation row still uses the document field. An empty menu title still uses the localized pagetitle. The previous fallback stays when the setting is off.
- With `localizator3_default_from_resource`, a missing translation row clears the same resource fields as an empty cell. The menu title stays on the document value because there is no localized pagetitle. The setting off still leaves those fields on the document.
- `FetchLocalizator` joins localized TVs by name through `localizator3\locTemplateVarResource`. The previous select returned the TV id, so the join stayed on the document TV table.
- Saving a static resource updates `content` only for the default language, the same as a symlink or weblink. Other translations keep their content.
- With `localizator3_default_from_resource`, an empty localized TV is cleared on the page. The value `0` is still treated as filled.
- `getLocalizedSitemap` without parameters lists the site from parent `0`. An empty `parents` property no longer produces an empty urlset. The documented scheme default is `0`.
- `makeLocalizedUrl` resolves a language key in any case before loading the active language.
- `x-default` uses the default language key. The hreflang value stays the cultureKey.
- Language names, CSS classes and URLs in the language chunks are escaped. A URL scheme other than http or https is dropped. The dropdown option receives `rowClass`.
- `getLanguageList` registers its parameters. `getLocalizedResources` registers `onlyWithLocalization`. Empty `tpl`, `pageId` and `where` still use the snippet defaults.
- A cultureKey is added to the language map only when that lookup is free, so it does not replace another language key.
- `localizator3_default_translator` must be one of SimpleCopy, Yandex, Google, DeepL, LibreTranslate or MyMemory. Any other value loads SimpleCopy.
- Lexicon translation skips a language when `localizator3_check_permissions` is on and `localizatorcontent_save_{key}` is missing.
- In a web context, `getLocalizedField` and `makeLocalizedUrl` ignore unpublished and deleted resources.

## [1.1.4-beta] - 2026-11-23

### Fixed
- `getLocalizedField` and `locfield` accept a language key in any case (`EN` and `en`). On the current language they return the same value as the resource field. A request for another language finds the translation by key or cultureKey, including a translation the page already shows.
- With `localizator3_default_from_resource`, `getLocalizedField` and `locfield` no longer copy the document field into another language. An empty translation stays empty. On that language an empty overlay clears the resource field. The menu title still falls back to the localized pagetitle.

## [1.1.3-beta] - 2026-11-22

### Fixed
- A language root without a trailing slash (`/en`) redirects with 301 to `/en/` before the root language is chosen. `/en/` still matches a language host stored with or without that slash. Deeper paths such as `/en/page` are not redirected.
- An empty localized menu title no longer leaves the document menu title in the menu. The localized pagetitle is used instead, both on the page and in `getLocalizedResources`.
- `{$_modx->resource.localizator3_content}` is set for every language. The default language and an empty content translation use the document content.

## [1.1.2-beta] - 2026-11-22

### Fixed
- `getLocalizedSitemap` with `onlyWithLocalization` no longer fails on `GROUP BY key` (`key` is reserved in MySQL 8) and counts only active translations.
- `getLocalizedCanonical` `tpl` accepts `@INLINE` and keeps the default `<link>` markup when the chunk name does not exist.
- `getLocalizedCanonical` and `getLocalizedSitemap` sort languages by `` `rank` ``. MySQL 8 treats `rank` as a reserved word, so the unquoted ORDER BY aborted both snippets.
- `makeLocalizedUrl` no longer appends the current `base_url` to the site start, so the homepage is `/` or `/en/` instead of `/en/en/`. `makeLocalizedUrl` and `getLanguageList` take the scheme from the secure request (`HTTPS`, `X-Forwarded-Proto`), not from an empty `server_protocol`.
- `site_url` uses `https` when the request is secure via `HTTPS`, port 443, `X-Forwarded-Proto` or `X-Forwarded-Ssl`, even if `MODX_URL_SCHEME` is still `http`. `base_url` stays the language path (`/` or `/en/`). The language cookie gets the `Secure` flag on the same check.
- `getLocalizedResources`: join uses the xPDO alias (`modResource`), not the fully-qualified class name. The language key is in the JOIN `ON` clause, so `pdoMenu` / `pdoResources` still list resources that have no translation. Empty localized fields fall back to the resource document.
- Empty localized fields no longer overwrite the resource on `OnLoadWebDocument`. `getLocalizedField` reads the document column from the database when the translation is empty.
- Upgrade fills empty `languages.tpl` and `languages.dropdown.tpl` from the package templates and leaves a non-empty chunk body unchanged.
- Element descriptions (`localizator_chunk_*`, `localizator_snippet_*`, `localizator3_plugin_desc`) resolve from the lexicon in the manager. Saving an untouched description keeps the lexicon key.

## [1.1.1-beta] - 2026-11-13

### Added
- `ModxPro\PdoTools\FetchLocalizator` in `src/FetchLocalizator.php` (PSR-4) for pdoTools 3 localized TVs (#31).

### Changed
- `localizator::getDefaultLanguageKey()` caches the resolved key in `$defaultLanguageKeyCache`.
- `getLocalizedCanonical`: simplified `$currentKey` check.
- `pdofetchlocalizator3.class.php`: dropped conditional `require_once pdofetch.class.php` (pdoFetch autoloads in pdoTools 3); `$prepareTypes` caches TV sources in `prepareRows()`.
- Composer PSR-4 autoload for `ModxPro\PdoTools\` → `src/` in the component `composer.json` (#31).
- Resolver sets `pdotools_fetch_class = ModxPro\PdoTools\FetchLocalizator` for pdoTools 3 (#28, #31).

### Fixed
- Localization tab document `content` (and richtext without custom TV HTML): mount MODX RTE / Ace via `RichtextField` + `MODx.loadRTE`, sync on save (`tinymce.triggerSave`). Init waits until the ExtJS Localization tab (and the textarea) is visible — TinyMCE fails when the field mounts while the tab is still hidden.
- After Save, TV richtext editors no longer stay as plain textareas: destroy stale TinyMCE instances before re-rendering `TvRenderedInput` HTML, and re-init when the editor is not bound to the current textarea.
- `#38` `FetchLocalizator` autoload: PSR-4 in component `composer.json`; namespace `bootstrap.php` requires `vendor/autoload.php` before OnMODXInit so pdoTools can `new` the class. Plugin also loads autoload on `OnMODXInit` (priority `-1000`) as a fallback.
- `#37` `getLocalizedSitemap`: `array_filter` without callback dropped `'0'`; use `strlen` filter. Call `getChildIds` per parent (MODX 3).
- `#35` `getLanguageList`: pass `outerClass` into the languages chunk.
- `#34` Transport build: `snippet.` / `chunk.` file prefixes so snippets and chunks ship with real content.
- `#32` Translate processors and CLI use `getDefaultLanguageKey()` (fallback when setting empty).
- `#30` Empty `localizator3_default_language` falls back to first active language by rank/id.
- `#29` `getLocalizedCanonical` / `getLocalizedField` without `&id` use the current resource (`null` property default).
- `#28` pdoTools 3: resolver updates `pdotools_fetch_class` (not legacy `pdoFetch.class`) on upgrade.

## [1.1.0-beta] - 2026-11-13

### Added
- PrimeVue theme via VueTools (`@vuetools/useTheme`): always ModxManagerTheme (`getActiveTheme('modx')`). New `vueManager/src/app/primevueTheme.js` with `getManagerPrimeVueConfig()` and `getPrimarySaveSeverity()` (always `success` for Save/Add). Localizator3 ignores the VueTools `vuetools.theme` / Aura setting.
- Lexicon keys `localizator_content_active` / `localizator_content_active_desc` for the "Publish translation" control on the Localization tab.

### Removed
- Unused Vue components `ContentFormDialog.vue` and `LanguageFormDialog.vue` (forms live in `ContentGrid` / `LanguagesGrid`).

### Changed
- Vue manager grids use shared composables (`useConnector`, `useLexicon`, `useDataTable`, `useGridCrud`, `useConfirmAction`). Content localization logic lives in `useContentForm.js` so `ContentGrid.vue` / `LanguagesGrid.vue` stay under the 400-line gate.
- Manager Vue UI chrome matches MODX / VueTools: green `#6cb24a`, 13px type, 32px controls, resource-like form tabs, flat panels. Languages page paints `#modx-content`; the resource Localization tab does not hide the host ExtJS panel.
- Languages page layout: page title, compact stats strip, search without a redundant label (16rem), primary action on the right.
- Localization toolbar: constrained language select, publish checkbox next to it (description in `title`), Save uses theme severity, Translate is outlined secondary.
- `createLocalizatorApp` uses ModxManagerTheme; theme options use `darkModeSelector: '.modx-dark-mode'` and `cssLayer: false`.
- `resolver_11_upgrade.php` no longer bulk-enables every TV on install. New TVs stay off until `localizator3_enabled` is set on the TV form. The unused `localizator3_tv_fields` system setting is removed if present.
- Localization tab: the language comes only from the toolbar select. The form `key` field is hidden (#19). The "Publish translation" checkbox sits in that toolbar and is checked when the value is `1`.
- `richtext` TVs use the MODX editor (`MODx.loadRTE` or Ace), the same editor as the resource form. The TV description sits next to the label. Placeholders that repeated the field caption are removed.

### Fixed
- Nested MIGX auto-translate: `configs` / `formtabs` from a child field are written to the nested TV `input_properties` before the recursive `translateTV()` call. Sibling fields no longer inherit a polluted parent `$params` bag. Nested migx via `inputTVtype` + config name (or inline formtabs) is translated, not only `inputTV` references.
- TV participation in localization: new TVs default to off (`localizator3_enabled=0`). The localization tab shows and saves only TVs enabled on the TV form. The installer used to enable every TV.
- MODX 3 `modTemplateVar` xPDO map merge: the class key is `MODX\Revolution\modTemplateVar`, not the legacy `modTemplateVar` (`OnMODXInit` and the resolver). The whole map is written back, because nested `$modx->map[$class][$key]` does not persist in MODX 3 (xPDOMap returns a copy). The `localizator3_enabled` column is added on install and upgrade.
- The "TV is available in localizations" checkbox is saved. `OnTVFormSave` stores `0` when the box is cleared. ExtJS does not post `0`, so without the handler a TV could not be turned off.
- `getformconfig`, `localizatorContent`, `fields`, and `pdofetchlocalizator3` check the physical column, not only the map. Installations without the column keep the previous behavior and do not throw SQL errors.
- `localizatorContent::renderTVOutput()`: the missing `localizator_is_mod_template_var()` call is replaced with `instanceof modTemplateVar`. Localized TV output no longer fatals.
- Languages grid "Active" column: `getlist` returns a strict `bool`. The UI coerces `0/1/'0'/'1'` to `bool` in the grid, the toggle, and the stats. Stats count every language, ignoring the search filter. Status tags use Active / Disabled lexicon keys instead of Enable / Disable action labels.
- Content form tabs sit flush with the panel top (PrimeVue `.p-tablist` padding removed).

## [1.0.12-beta] - 2026-11-06

### Fixed
- TV fields on the Localization tab render by type. `number`, `listbox`, `listbox-multiple`, `checkbox`, `radio`, and similar types use PrimeVue controls. MIGX, tvmedia3x, and other custom types use the MODX renderer. Every TV used to be a plain textarea.
- Custom TV values (MIGX, tvmedia3x, and others) are collected and saved per localization. Generated field ids do not collide with TVs on the main resource form.

## [1.0.11-beta] - 2026-10-07

### Added
- Setting `localizator3_request_language_param` (default `language`): a GET/POST parameter with an explicit language key. It outranks the `localizator3_key` cookie in connector/AJAX requests and in auto-detect redirects. An empty value disables the override. Example: `?language=ru` while the cookie is `en`.
- `localizator::getRequestLanguageKey()` and `applyLanguageFromKey()` read that parameter and sync `cultureKey` / `localizator3_key`.

### Changed
- `resolveConnectorLanguage()` order: request parameter, Referer path, HTTP host, cookie.
- `applyLanguageFromCookie()` delegates to `applyLanguageFromKey()`.

---

## [1.0.10-beta] - 2026-07-17

### Added
- `localizator::applyLanguage()`, `applyLanguageFromCookie()`, and `resolveConnectorLanguage()` sync the language outside a full page request.

### Fixed
- Connector / AJAX: `OnMODXInit` calls `resolveConnectorLanguage()` (Referer path or the `localizator3_key` cookie). Language used to be set only when `X-Requested-With: XMLHttpRequest` and a Referer were both present, so package `connector.php` calls kept the system `cultureKey` (often `ru`) while the storefront was already `en`.

### Changed
- Language application moved out of `findLocalization()` into `applyLanguage()` so other callers can reuse it.

## [1.0.9-beta] - 2026-07-07

### Added
- Setting `localizator3_default_from_resource`: default-language content (`localizator3_default_language`) comes from the resource fields and TVs. The Localization tab lists translations only.
- `localizator::shouldUseResourceFields()`, `getLocalizedFieldValue()`, `buildDefaultLanguageSource()`, and `localizatorContent::hydrateFromResource()`.

### Fixed
- PHP 8: `findLocalization()` no longer passes `$request` by reference. `OnHandleRequest` and `OnMODXInit` pass the request path through a variable. This removes the frontend fatal "could not be passed by reference".
- Install on PHP 8.2: Symfony 7 instead of 8 in vendor, platform PHP 8.2, and a corrected `platform_check.php` (#8).
- VueTools resolver: `modTransportProvider::request()` is called with the MODX 3 signature, through a shared helper. A VueTools failure does not abort the Localizator3 install (#8).
- Phinx migrations: MODX `table_prefix` is no longer applied twice. The migration log table is `{table_prefix}localizator3_migrations`. A repair runs before Phinx on installations that were already broken (#9).
- Package uninstall: the `localizator3` plugin and its events are removed by a resolver and transport attributes (`UNINSTALL_OBJECT`) (#10).

## [1.0.8-beta] - 2026-06-17

### Fixed
- Resource Localization tab: Vue mount race. The bridge does not set `data-mounted` until `app.mount()`, and retries while the ES module is still loading.
- Mount recovery: a stuck `data-mounted` flag without `.content-grid` is cleared. The tab `activate` handler and `doLayout` run after mount.
- Localization tab: language select and an inline Document / TV form replace the grid list. Save stays on the tab.
- Locale dropdown: every active Localizator3 language. Switching loads an existing translation or starts a new one for that key.
- Full width of the localization tab: ExtJS `layout: anchor` and `anchor: 100%`, plus CSS from `#localizator3-resource-tab` to `#localizator3-content-app`.
- CSS: `index.min.css` renamed to `content.min.css` in `OnDocFormPrerender.php`.
- Build: `languages.min.js` is emitted.
- Vite: `inlineDynamicImports: true`. Each entry is one file, with no code-split chunks.

### Added
- VueTools ≥1.1.2-pl: Vue 3, Pinia, and PrimeVue 4 through an Import Map.
- `vuetools` resolver: checks for VueTools and installs it.
- Trait `Localizator3VueControllerTrait` with `requireVueTools()` and `addVueModule()`.
- Composables: `useConnector`, `useLexicon`, `useDataTable`, `useGridCrud`, `useConfirmAction`.
- Shared components: `FormFieldRenderer.vue`, `GridActionsColumn.vue`.
- Dialog components: `ContentFormDialog.vue`, `LanguageFormDialog.vue`.
- Lexicon entry `localizator3_vuetools_required` when VueTools is missing.

### Changed
- Docs: one `docs/` tree (kebab-case), index in `docs/README.md`, Vue UI and getformconfig brought up to date.
- Vite `external` for `vue`, `pinia`, `primevue`, `@vuetools/*`. Bundles are about 14 KB instead of about 800 KB.
- `createLocalizatorApp.js`: one Vue bootstrap without Pinia (stores are unused).
- ExtJS fallback for the grids is removed. The manager UI is Vue and requires VueTools.

## [1.0.1-beta] - 2026-06-17

## [1.0.0-beta] - 2026-06-17

### Added
- First release, MODX 3 only.
- Fork of Localizator adapted for MODX Revolution 3.
- Separate package name (`localizator3`) and tables (`localizator3_*`), so it does not clash with the original Localizator.
- MODX 3 namespaces (`\MODX\Revolution\*`, `\xPDO\Transport\*`).
- MODX 3 only, with no MODX 2 compatibility layer.
